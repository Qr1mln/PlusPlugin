# 定时任务（进程内调度）

> 状态：2026-10-26 已实现并端到端验证（一次性任务按时触发 → `load`+`play` → `done`）。

## 1. 形态

- **执行在 DLL 内**：`plugin/script-engine/schedule.cpp` 起一个调度线程，到点把脚本作为 `load`+`play` 压进引擎命令队列，**不经过 TCP，编辑器关掉也照跑**。
- **配置是 JSON**：`%APPDATA%\TTVoice\schedule.json`，由编辑器写、DLL 只读。
- **管理界面在编辑器**：主界面「脚本列表」工具条上的 **定时任务** 按钮，打开独立弹窗（列表 + 表单）。

## 2. 配置格式

```json
{
  "version": 1,
  "jobs": [
    {"id": "j1", "name": "每天上麦", "scripts": ["进房间", "上麦", "退出房间"],
     "enabled": true, "loop": 1,
     "when": {"type": "daily", "at": "21:30", "days": [1, 2, 3, 4, 5]}},

    {"id": "j2", "name": "每 30 分钟", "scripts": ["xxx"],
     "enabled": true, "when": {"type": "interval", "minutes": 30}},

    {"id": "j3", "name": "一次性", "scripts": ["xxx"],
     "enabled": true, "when": {"type": "once", "at": "2026-10-27 21:30"}}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `scripts` | **有序脚本列表**：`<目录>/<名称>.json` 的名字（不含扩展名），按数组顺序依次执行 |
| `dir` | **脚本目录**（可选）：留空 = `%APPDATA%\TTVoice\scripts`；相对路径相对该根目录（如 `活动A`），也可填绝对路径 |
| `gap_ms` | **脚本间隔**（毫秒，默认 0）：每个脚本跑完后、下一个脚本开始前等待这么多久；**最后一个脚本后不加** |
| `script` | 早期单脚本字段；仍能读入（自动当成 `scripts: ["x"]`），编辑器保存时统一改写为 `scripts` |
| `enabled` | false 时完全不参与调度 |
| `loop` | 覆盖脚本自带的 loop（>1 时生效，**对任务里每个脚本都生效**） |
| `when.type` | `daily`（默认）/ `interval` / `once` |
| `when.at` | `daily` 用 `HH:MM`；`once` 用 `YYYY-MM-DD HH:MM`，都按**本地时间** |
| `when.days` | `daily` 的星期过滤，`1`=周一 … `7`=周日；空数组 = 每天 |
| `when.minutes` | `interval` 的间隔分钟数（≥1） |

## 3. 已定语义（改之前先看这里）

1. **多脚本顺序执行**：一个任务带 N 个脚本时，触发瞬间按顺序压 N 对 `load`+`play`；执行线程串行消费队列，所以**前一个脚本完全跑完才开始下一个**（日志里 `sched: run job=.. step=1/N ..` 会一次全打出来，实际执行是排队的）。
1.1 **立即执行**（`run_scripts`）：走同一条队列，日志前缀是 `run=manual`（`sched: run run=manual step=1/2 script=...`），因此在脚本正在跑时点它同样是排队、不打断。
1.2 **脚本间隔**（`gap_ms`）：在相邻两个脚本之间压一个 `Delay` 命令（执行线程分片睡眠、可被「停止」打断），日志打 `gap: 500 ms`；最后一个脚本之后不加间隔。定时触发与立即执行共用同一逻辑。
2. **单个脚本坏掉不影响后续**：某个脚本文件缺失或解析失败，记一行日志后跳过，继续下一个；全部失败才打 `sched: 任务 xx 没有可执行的脚本`。
3. **忙则排队**：脚本正在跑时到点，`load`/`play` 进队列，等本轮结束立刻执行（不丢弃）。执行线程本身串行处理队列，天然满足。
4. **不补跑**：应用重启或休眠唤醒后，错过的时间点直接跳过，只从"下一次未来时刻"开始。
5. **once 一次性**：触发后本次进程内不再重复（内存里标记；`reload` 配置会复位）。
6. **无配置 = 不调度**：文件缺失时打一行 `sched: 没有 ... 定时任务为空`，不影响引擎。
7. **时间用本地时间**，`daily` 用 `mktime`（`tm_isdst=-1`）算，夏令时由 CRT 归一化。

## 4. DLL 侧实现要点

- 循环：算"最近的下次触发"→ `cv.wait_until`；**最长只等 30 秒**后重算，用来兜住系统休眠/时间回拨/配置更新。
- 脚本读取：`%APPDATA%\TTVoice\scripts\<name>.json`，用 nlohmann 解析 `events`/`loop`（字段与编辑器保存格式一致）。
- 日志：`sched: 已加载 N 个任务（M 个待触发）` / `sched: run job=t2 step=1/2 script=_a events=.. loop=..` / `sched: 任务 t2 第 2 个脚本找不到（...）` / `sched: 配置已重新加载`。
- 生命周期：`init` 里 `sched::Start()`，`shutdown` 里 **先 `sched::Stop()` 再 `tcp::Stop()` 再 `se::Shutdown()`**（避免调度线程在引擎收尾时再压命令）。

## 5. 协议（编辑器 ↔ DLL）

帧格式不变（4 字节长度 + UTF-8 JSON），新增两条命令：

| 方向 | 帧 | 说明 |
|---|---|---|
| 编辑器 → DLL | `{"cmd":"get_schedule"}` | 请求当前任务状态 |
| 编辑器 → DLL | `{"cmd":"reload_schedule"}` | 同步重读 `schedule.json` |
| 编辑器 → DLL | `{"cmd":"run_scripts","scripts":["a","b"],"loop":N,"dir":"活动A","gap_ms":500}` | **立即执行**：按顺序压入 load+play，不依赖已保存的配置；`dir` 省略即默认目录，`gap_ms` 省略即 0 |
| DLL → 编辑器 | `{"t":"schedule","now":"...","jobs":[{"id","name","scripts":[...],"enabled","type","next"}],"next":"...","next_id":"..."}` | `get_schedule` / `reload_schedule` 回这一帧 |
| DLL → 编辑器 | `{"t":"ok","what":"run_scripts"}` | `run_scripts` 的入队回执（**立即**返回，不等脚本跑完） |

注意：DLL 是**单客户端顺序服务**，脚本正在执行时第二条连接会排队等（编辑器侧 `engine_call` 有 3 秒超时，超时会提示"引擎未响应"）。

## 6. 编辑器侧

新增 `editor/schedule.py`：

- `load_jobs()` / `save_jobs()`：读写 `schedule.json`，写入走 `临时文件 + os.replace` 原子替换，DLL 不会读到半个文件。
- `describe_when(job)`：把触发条件格式化成「周一二三四五 21:30」/「每 30 分钟」/「一次性 …」。
- `job_scripts(job)`：取有序脚本列表（兼容旧 `script` 字段）。
- `engine_call(cmd, want)`：短连接发一条命令并取回指定类型的帧（跳过 `log` 帧）。
- `ScheduleDialog`（纵向：设置在上、列表在下）：上方表单（名称、**脚本目录**（输入框 + 浏览 + 默认）、**脚本序列**（下拉 + 添加 + 上移/下移/移除，下拉只列当前目录里的脚本）、触发类型、时刻或间隔、星期勾选、轮数、**脚本间隔（毫秒）**、启用、新增/应用修改/删除），下方任务列表（启用 / 名称 / 触发 / 下次运行），底部「保存并生效」（写文件 + `reload_schedule`）、**「立即执行」**（对选中任务发 `run_scripts`，不必先保存）与「刷新状态」（`get_schedule`）。脚本序列只在表单里编辑，列表不再展示。
- `editor/timepicker.py`：**一次性时刻用弹窗选择器**（`DateTimePicker`，纯 tkinter：月份日历 + 时分 Spinbox + 「此刻」「确定/取消」，回车确认、Esc 取消），确认后回写 `once_var`。`daily` 的时刻仍是 `HH:MM` 输入框。

主界面入口：`editor/app.py` 的 `open_schedule()`（单实例，已开则提到前面并刷新状态）。
