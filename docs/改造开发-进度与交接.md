## 1. 技术路线演进（为什么是现在这套）

1. **架构分析** → 报告见 `docs/TTVoice-架构分析与健壮性测试报告.md`。
2. **候选方案对比**（源码接入 / H5 / 资源替换 / AOT 补丁 / DLL 注入 / 伴程 Overlay）→ 用户选定 **DLL 代理 + 注入式渲染**（保真度最高、不改主程序）。
3. **静态选点**：`TTVoice.exe` 静态导入 `dwmapi.dll`（安装目录无同名文件、非 KnownDLL）→ 首选 `dwmapi.dll` 作为代理名。
4. **代理实现**：MSVC 的 `.def` 转发语法不可用（实测 44 个 LNK2001）→ 改为 **AheadLib 风格 stub**：`stubs.asm`（`jmp qword ptr [g_pfn_X]`）+ `DllMain` 内 `LoadLibrary(System32\X.dll)` 解析真身。
5. **dwmapi 代理翻车**：启动弹「无法定位序数 137 于 d3d9.dll」。实测 Windows 的 d3d9 无任何序号导出，应用/ANGLE/dcomp 全部按名字导入 → 根因是 **DllMain 内提前加载真 dwmapi，把 dcomp/图形栈拉起**的异常时序。
6. **改用 `version.dll` 代理**（17 个导出、真身只依赖 kernel32、与图形栈无关）→ P0 一次通过。
7. **Present hook**：patch `IDXGISwapChain` 共享 vtable（Present=8 / ResizeBuffers=13 / Present1=22），用临时 swapchain 取 vtable。
8. **窗口匹配**：swapchain 挂在 `FLUTTERVIEW` **子窗口**上（`out != 主窗口 hwnd`）→ 改为 `GetAncestor(GA_ROOT)` / `GW_OWNER` 关系匹配。
9. **D2D 失败**：`ID2D1Factory1::CreateDevice` 返回 `0x80070057`（ANGLE 设备未带 `D3D11_CREATE_DEVICE_BGRA_SUPPORT`）→ 先用 `ID3D11DeviceContext1::ClearView` 兜底（矩形可见，P1 通过）。
10. **BGRA 修复**：`libGLESv2` 是动态 `LoadLibrary("d3d11.dll") + GetProcAddress`，IAT 里没有 d3d11 → 改为 **hook `GetProcAddress`** + `LdrRegisterDllNotification` + 在 `DllMain` 尽早启动线程 → 拦截成功，D2D 走通（文字按钮可见）。
11. **位置与配置**：按钮移到顶栏，坐标/尺寸/文案改为读 `%APPDATA%\TTVoice\overlay.ini`，便于微调。

```ini
; --- 视觉门控（脚本的 wait_px 用）---

; 整块关掉面板请用 log_on_screen=0（单靠 log_lines=0 只是不留镜像行）

```

> 脚本的 `wait_px` 门控不用固定延时（实测 600ms 稳定偏早）：抓帧检测到奶油色像素（`R>228,G>210,B<228,R−B>22`）
> 达到 `wait_px` 且**连续三次轮询命中**（约 240ms 不动）才执行本行；日志会打印命中像素数与质心，便于判断是“没出现”还是“位置变了”。

> 注意：`font_size` 用的是**逻辑 px**，旧 ini 写 `14` 时实际渲染只有 14 物理 px（比应用小 40%）。
> 想让字号和应用一致需改成 `15`（22.5 物理 px，应用实测 em≈22.6 px）。
> 新键缺失时用上面的编译期默认值，因此旧 ini 不删也能生效（但 `font_size=14` 会被沿用）。

### 点击脚本（JSON）

叠加层按钮**只跑脚本**，没有任何兜底（ini 硬编码的两段点击链已删除）：`ScriptReload` 找不到文件就打 `script: no json found, the button does nothing`（**每次点按钮都会重打这行原因**，见下文），点下去不会有任何动作。

```json
{
  "version": 1,
  "name": "活动",
  "hotkey": "",
  "loop": 1,
  "events": [
    {"x": 27,   "y": 113, "click": "left", "delay_ms": 600, "wheel": 0, "text": "", "wait_px": 0,  "wait_max_ms": 0},
    {"x": 1573, "y": 87,  "click": "left", "delay_ms": 0,   "wheel": 0, "text": "", "wait_px": 40, "wait_max_ms": 4000}
  ]
}
```

| 字段 | 含义 |
|---|---|
| `x,y` | 逻辑 px（96 dpi）、`FLUTTERVIEW` 客户区相对，与 ini 同一坐标系 |
| `click` | `left` / `double` / `right` |
| `delay_ms` | 本行**执行完**之后的等待（下一行开始前） |
| `wheel` | 滚轮格数，正 = 上、负 = 下（0 不滚） |
| `text` | 非空时先把文本写进剪贴板，再 `SetForegroundWindow` + `SendInput Ctrl+V`（**需 TTVoice 前台**） |
| `wait_px` | 门控：本行执行前，等到 `(x,y)` 周围奶油色像素 ≥ 此值（连续 3 次命中）；0 = 不等 |
| `wait_max_ms` | 门控上限，超时照常执行本行（不中止） |
| `loop` / `hotkey` | 整份脚本重复轮数 / 可选全局热键（`F1`~`F24`、单字母或数字；空 = 不注册） |
| `view_size` | `[w,h]`：编辑器保存时的 view 客户区尺寸。**DLL 不认这个键（`JsonSkip` 直接跳过）**，只给编辑器用来提醒「坐标基准变了会偏」 |

**热加载**：DLL 每次执行前比对文件修改时间（`script: loaded ...`），在编辑器里保存后**点按钮即生效，不用重装 DLL、不用重启应用**。
选脚本优先级：`overlay.ini` 的 `script=` > `scripts\active.txt`（编辑器保存时写）> `scripts` 下最新的 `*.json`。

> **空脚本会被 DLL 拒收**：`JsonParseScript` 的收尾判据是 `count > 0`，所以 `events: []`（刚点「新建」就保存）
> 会打 `script: parse failed <path> (no events / bad json)`，常驻状态行变“脚本不可用…”。两段点击链删除后，
> 这时点按钮**真的什么都不做**；但日志里**每次点击都会重打一行原因**（按钮走 `ScriptTryRun(true)`：
> `no json found` / `parse failed` 不再被一次性抑制；被拒收的文件即使没修改也会重复打，原因存在 `g_scriptErr`）。
> 2s 轮询线程传 `false`，那里仍是一条只打一次（否则日志每两秒刷一行）。
> 真机实测过：编辑器「dll view」预演的结果与 DLL 自己打的那行完全一致。
> 同理：`script=` 指向不存在的文件时 DLL 直接当「没脚本」处理（`no json found`），**不会**继续往下看 `active.txt`。

### 界面日志（overlay 上的 tail -f 面板）

`log_on_screen=1` 时，每一条写进 `%TEMP%\tt_version_proxy.log` 的日志也会进一个 24 行环形缓冲，
并在叠加层**左下角**画最近 `log_lines` 行（半透明黑底；带 `fail/timeout/ignored/not seen` 等字样
的行用琥珀色）。这是调坐标/看门控命中最快的反馈通道，不用切出去翻文件。
面板**不淡出**：新行永远画在最底下、把最旧的一条推出窗口（tail -f 的观感），有内容就一直待着。
每一行（包括常驻状态行）前缀 `[HH:MM:SS.mmm]`：连点「活动」时正文是逐字符相同的两行在循环，
没有时戳的话 6 行窗口永远长一个样，容易被当成「面板卡住不滚」（踩坑 23 同时修了 ini 重复追加）。

- 配置只在启动时读一次：改 ini 需重启应用才生效；嫌面板占地方就调小 `log_lines`，要完全关掉用 `log_on_screen=0`。
- `log_seconds`（淡出计时）已整块删除：`g_logSeconds` / `g_screenLogStamp` 都不存在了；旧 ini 里残留这一行会被忽略，DLL 会打一行 `config: log_seconds is gone, the log panel stays on screen` 提醒。
- 旧的 `overlay.ini` 里没有这三个键时，DLL 会自动在文件末尾追加一段（值与默认相同），所以升级后直接打开 ini 就能看到、改完重启即生效；`log_lines=0` 只停镜像行（常驻状态行照画），整块关掉用 `log_on_screen=0`。
  **追加只会发生一次**：早期版本的追加判据跑在解析循环之后，而循环把每个 `=` 原地改成了 NUL，导致 `strstr("log_on_screen=")` 永远失败、每次启动都多一段（踩坑 23）。你的 ini 里现在已有 6 段旧块（5 段旧的 `log_lines=3` + 1 段新的 `log_lines=6`，后面的覆盖前面的，所以当前生效的是 6），手删重复段即可，新 DLL 不会再长。
- 只有 D2D 路径能画字：若日志出现 `overlay: using d3d11 fallback (no text)`，界面日志不会出现，只能看文件。
- 日志线程很多（UI/脚本/热键/Present），环形缓冲用 `SRWLOCK` 保护；写入失败（比如取不到字集）会自动 `log_on_screen=0` 并打一行 `log: no text format for the on-screen log`。
- 缓冲只有 24 行、也没有人工翻页：想看窗口之外的历史仍然只能去文件里看（或先把 `log_lines` 调大）。
- 面板不做去重/计数合并：同一个错误刷 10 次就是占 10 行，靠时戳区分。

**常驻状态行**（画在日志块第一行，琥珀色）——回答「现在到底有没有脚本在接管按钮」：

| `ScriptReload` 的结果 | 常驻行文字 | 胶囊文字 |
|---|---|---|
| 没找到任何脚本文件（含 `script=` 指空） | 「没有激活的脚本，点按钮不会有动作」 | 换成 `no_script_text`（默认「无脚本」） |
| 文件在但被拒收（坏 JSON / 事件表空） | 「脚本不可用（no events / bad json），点按钮不会有动作」 | 不变（仍是 `text`） |
| 脚本正常 | 清空（不占行） | 不变 |

- 状态由 `ScriptHotkeyThread` 的 2s 轮询刷新，所以在编辑器里保存后最多 2 秒胶囊就会变回去；`SetScriptStatus` 只在三个出口调用（mtime 未变时不重复写）。
- 只有「根本没有脚本文件」这一种改胶囊文字；其他问题一律只给日志提示，不顶掉你调好的顶栏外观。
- `log_on_screen=0` 时状态行也不画（共用一个绘制开关）。

## 3. 关键实测数据

| 项 | 值 |
|---|---|
| 主窗口 | class `FLUTTER_RUNNER_WIN32_WINDOW`，DPI 144（150%），客户区 1930×1206 逻辑 / 2896×1809 物理 |
| swapchain 窗口 | `FLUTTERVIEW` 子窗口（`OutputWindow != 主 hwnd`） |
| 渲染后端 | ANGLE → D3D11（`libEGL`/`libGLESv2`/`d3d11`/`dxgi`/`dcomp`，无 vulkan） |

## 6. 踩坑清单（含原因与修法）

| # | 现象 | 原因 | 修法 |
|---|---|---|---|
| 1 | `C2065 未声明` + `C4819` | UTF-8 无 BOM + 中文注释，MSVC 按 CP936 解析吞掉下一行 | 纯 ASCII 注释 + `/utf-8` |
| 2 | 日志缺失 | `fwprintf` 与 `vfprintf` 混用同一 `FILE*` | 统一窄字符流 |
| 3 | 44 个 `LNK2001` | MSVC `.def` 的 `A=B.C` 不被当作 PE 转发器 | 改 stub + 运行时解析 |
| 4 | `LNK2019 __imp_IsWindowVisible` 等 | 未链接 user32.lib | 链接行加 `user32.lib` |
| 5 | `此时不应有 not` | `echo` 文本含 `(...)` 提前闭合 if 块 | 去掉括号 |
| 6 | `ID2D1Device` 未声明 | 只包含 `d2d1.h` | 加 `d2d1_1.h` / `d2d1_1helper.h` |
| 7 | `CreateDevice` / `DrawTextW` 不存在 | 属于 `ID2D1Factory1` / 方法名为 `DrawText` | 改类型与调用 |
| 8 | 创建 swapchain 失败 | `D3D_DRIVER_TYPE_NULL` 不支持 swapchain | HARDWARE → WARP |
| 9 | 画到错误缓冲 | flip-model 下 `GetBuffer(0)` 轮转 | 按纹理指针缓存 RTV/Bitmap（≤4） |
| 10 | 没有 `present hook hit` | swapchain 在 `FLUTTERVIEW` 子窗口 | `GA_ROOT` / `GW_OWNER` 关系匹配 |
| 11 | `d2d CreateDevice hr=0x80070057` | ANGLE 设备无 `BGRA_SUPPORT` | hook `GetProcAddress` 补 flag（IAT 钩不到动态加载） |
| 12 | 启动弹「序数 137 于 d3d9.dll」 | dwmapi 代理在 DllMain 内提前拉起 dcomp/图形栈 | 换 `version.dll` 代理名 |
| 13 | 叠加层文字明显小于应用 UI | `font_size` 被直接当 DIP 画在 96 dpi 位图上，没乘 DPI scale | 建 `IDWriteTextFormat` 时乘 `g_scale`；默认改 15 逻辑 px |
| 14 | 后台窗口截不到内容 | 窗口非前台 + ANGLE flip-model | `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT)`，不需前台即可取全画面（量坐标/取色用） |
| 15 | 第 2 段点击「点太快」 | 固定 `click_delay_ms=600` 靠猜：横幅胶囊是第 1 段跳转后由 Web 层才渲染出来，慢时远超 600ms | 改为视觉门控：抓 `FLUTTERVIEW` 找奶油色胶囊，连续 3 次命中（约 240ms 不动）才点。（后来「移除两段式」把整条链删了，同一套门控算法留在 `WaitForCreamAt` 里服务脚本的 `wait_px`） |
| 16 | Python 侧 `ctypes.wintypes` 没有 `BITMAPINFO` | 该模块只导出 Win32 基础类型，不含 GDI 的 DIB 头 | 在 `script_editor.py` 里自建 `BITMAPINFOHEADER`/`RGBQUAD`/`BITMAPINFO` |
| 17 | 未声明 `argtypes` 的 API 传 HWND 被截断 | ctypes 默认把 Python `int` 转 `c_int`（32 位），64 位 HWND 会被砍 | 所有涉及句柄的 API 都写 `argtypes`（`SetForegroundWindow`/`PrintWindow`/`GetDpiForWindow` 等） |
| 18 | tkinter 窗口在高 DPI 屏上“字大窗小” | Tk 按 DPI 放大字体（150% → `tk scaling=2.0`），但 geometry/列宽是裸像素 | 取 `winfo_fpixels("1i")/96` 作 scale，geometry/列宽/minisize 全部同步乘它 |
| 19 | 编辑器「试跑」正常、DLL 实跑位置/时机就是偏 | 两边各写一套语义：坐标 `int(round())` vs `static_cast<LONG>` 截断、门控先抓后睡 vs 先睡后抓、`wait_max_ms<=0` 时一边没上限 | 把 DLL 的常量集中成 `script_editor.py` 顶部的 parity 常量表（注释标「改一边必须改另一边」），日志字样用 DLL 原文，两边能逐行比对 |
| 20 | 后台线程读 `tk.BooleanVar` 报「main thread is not in main loop」 | Tcl 解释器不允许跨线程访问 | 勾选框 `command` 在 Tk 线程里把值同步到一个普通 bool，轮询线程只读那个字段 |
| 21 | `PrintWindow` 截普通窗口时底栏被切掉一截 | `PrintWindow` 画的是**整个窗口含标题栏**，DIB 却按 `GetClientRect` 建 → 内容整体下移，底部等量被裁 | 截无标题栏子窗口（`FLUTTERVIEW`）用 client 尺寸是对的；截带标题栏的窗口要改按 `GetWindowRect` 建 DIB |
| 22 | 文档与编辑器日志都写成「脚本被拒收 -> 点按钮什么都不做」，错的 | 没读调用点：`SimulateSidebarClick()` 是 `if (ScriptTryRun()) return;`，`ScriptReload` 失败时**照样往下跑 ini 两段链** | 写结论前先沿调用链确认；两边改成「退回 ini 两段链」，并用常驻状态行把这个分流直接暴露到界面上。**后续「移除两段式」删了兜底链，现在「什么都不做」反而是对的**，两边文案同步改成「点按钮不会有动作」 |
| 23 | `overlay.ini` 每次启动多一段重复的 `log_*` 配置（实测 6 次启动积了 6 段） | `LoadConfig` 的解析循环把每行的 `=` 原地改成了 NUL（`*eq = 0`），而追加判据 `strstr(buf, "log_on_screen=")` 跑在循环**之后** → 永远找不到 → 每次启动都追加 | 把追加/残留键（`log_seconds`）的探测全部提到解析循环**之前**（`hasLogKeys` / `hasFadeKey`）。 |
| 24 | 日志面板看起来「不滚」 | 不是环形缓冲的 bug（下标 0 最旧、末尾最新，取尾部 N 行本身就是时间序）：连点时两行正文逐字符相同，没有时间戳就看不出位移 | `PushScreenLog` / `SetScriptStatus` 统一走 `StampPrefix`，给每行加 `[HH:MM:SS.mmm]`（与文件日志同钟）；长行截断不用 `strncpy_s(_TRUNCATE)`（溢出会走 CRT invalid-parameter 处理器 → 带死宿主进程） |

6. **点击脚本化（P2-4 / P2-4b，已实现）**：定位是「DLL = 最终执行器，编辑器 = 开发调试台」，所以编辑器的执行路径必须与 `script_engine.inc` 逐条等价。
   - 编辑器：`python tools/script_editor.py` → 「添加坐标（拾取）」在 TTVoice 界面上点一下即记录（该次点击被钩子吞掉，不会触发应用）→ 「保存」写 `scripts\<名称>.json` + `active.txt`。
   - DLL 侧：叠加层按钮 → `ScriptTryRun(true)` → `ScriptReload(true)`（比对修改时间，变了才重解析；失败时**每次点击都重打原因行**）→ `ScriptRunThread` 逐行执行；**只有脚本**，没有可用脚本时点下去不做任何动作（ini 两段链已删除）。
   - **parity 常量表**（在 `script_editor.py` 顶部，注释已标「改一边必须改另一边」）：

     | 编辑器 | DLL 侧 | 值 |
     |---|---|---|
     | `GATE_POLL_MS` | `g_gatePollMs`（ini `gate_poll_ms`）/ 脚本门控轮询 | 120 |
     | `GATE_STABLE` | `WaitForCreamAt` 的 `++stable >= 3` | 3 |
     | `GATE_MAX_MS` | `WaitForCreamAt` 在 `maxMs <= 0` 时的 `limit` | 4000 |
     | `CREAM_MIN_PX` | 「门控检查（不点）」没写 `wait_px` 时的默认阈值 | 40 |
     | `DBLCLK_GAP_MS` | `SimulateClickKindAt` 的 `Sleep(40)` | 40 |
     | `PASTE_FOCUS_MS` | `PasteTextToApp` 的 `Sleep(80)` | 80 |
     | `MAX_EVENTS` / `MAX_TEXT` / `MAX_LOOP` | `kScriptMaxEvents` / `kScriptText-1` / `loop` clamp | 32 / 255 / 99 |
     | 坐标换算 | `static_cast<LONG>(lx * g_scale)` | **截断**，不是四舍五入 |
     | 消息序列 | `WM_MOUSEMOVE → LBUTTONDOWN/UP`（double 多一次 `DBLCLK`）；`WM_MOUSEWHEEL` 用**屏幕**坐标 | 一致 |
     | JSON 契约 | `click` / `hotkey` 是**字符串**（`ClickFromName` / `HotkeyFromName`），未知键 `JsonSkip` | 一致 |

   - **只有两处故意不同**（都是调试台该有的能力，且日志里会明说）：① 「停止」能中止，DLL 只能跑到最后一行；② 「门控检查（不点）」只跑门控判定 + 存抓帧，一个消息都不发（DLL 没这个开关，等满后照点）。
   - 日志窗格：字样与 DLL 完全一致（`script: run "..." events=N loop=N` / `script: click kind=K X,Y` / `script: wheel +N X,Y` / `script: gate hit Npx at X,Y after Nms` / `script: gate timeout Nms (max Npx)` / `script: done in Nms`），勾「跟随 DLL 日志」后能把 DLL 真写的行以 `[DLL]` 前缀拉进来逐行比对；保存后还会打 `dll view: script: loaded / parse failed ...`，预告「下次点按钮 DLL 会加载哪份、收不收」。
   - 日志自检链：`script: loaded <path> name="..." events=N loop=1` → `script: run "..." events=N loop=1` → 每行 `script: click kind=0 40,169`（或 `script: gate hit 1430px at 2359,131 after 1183ms` / `script: gate timeout 4000ms (max 0px)`）→ `script: done in Nms`。
   - 已知边界：`text` 粘贴依赖前台（先 `SetForegroundWindow` 再 `SendInput`）；脚本运行中再点按钮会被丢弃（`script: run ignored, previous run still active`）；单脚本最多 32 行、单条 `text` 255 字符（超出 DLL 静默截断，编辑器会先打 parity 警告）。
   - 下一步可选：脚本级「取消」（再点一次按钮中止）、条件分支（按像素/文字判断走哪条）、把「活动/续期」做成两份脚本用热键切换。
7. **界面日志（P2-5，已实现）**：`log_on_screen=1` 时日志同时画在叠加层左下角，**常驻不淡出**（tail -f：新行滚到最底、旧的推出窗口；默认 6 行，上限 24）。
   - 调用链：`LogFromOverlay`（唯一入口，已包住 `Log()`）→ `PushScreenLog`（拼 `[HH:MM:SS.mmm]` 前缀 + UTF-8→UTF-16，24 行环形缓冲，`SRWLOCK` 全程保护）→ `DrawScreenLog`（每帧取最近 `log_lines` 行，半透明黑底，失败/超时行琥珀色）。
   - 独立资源：`g_logFmt`（左对齐/顶端对齐/不换行，字号 `log_size × g_scale`）+ `g_logBrush`，与按钮的 `g_textFmt/g_brush` 完全分开，互不影响；创建失败只关掉界面日志（`log: no text format for the on-screen log`），按钮照画。
   - 自检：点叠加层按钮后左下角应依次出现 `[时戳] overlay: button clicked` → `[时戳] script: no json found, the button does nothing`（或 `script: run ...` → `script: click kind=0 40,169` → `script: done in Nms`）；连点时看到的就是时戳在跳。看不到就先查是否走了兜底（`overlay: using d3d11 fallback (no text)`）或 `log_on_screen=0`。
   - 为什么不用子窗口/Overlay 窗口：现成的 `Present` hook 里画零成本，不额外占窗口、不影响焦点；代价是只能在 D2D 路径可用。
8. **发布**：DLL/启动器代码签名、EDR 白名单沟通、更新后重新投放脚本。

## 9. 关键代码结构（overlay.inc）

> 本节描述**当前生效的单体老路径**（`overlay.inc` + `script_engine.inc`），按 `docs/plugin-framework.md` §8 规划，这部分将在 M1 改写为 `plugin_overlay/` 插件，hook 收进 `framework/render.inc`。迁移完成前本节仍是真实现状。

| 区块 | 作用 |
|---|---|
| 配置与全局状态 | 按钮几何（逻辑单位）、配色/描边/圆角、hover/pressed/clicks、设备与 D2D 对象 |
| `LoadConfig` | 读 `overlay.ini`，缺失时写模板；新键全部有编译期默认值。追加 `log_*` 段与探测残留键（`log_seconds`）必须在解析循环**之前**完成（循环会把 `=` 改成 NUL，踩坑 23） |
| `Utf8ToWide` / `ParseColor` | ini 值解析（UTF-8 文本、`#RRGGBB`/`#AARRGGBB`） |
| `ResolveFontPath` | `%ENV%` 展开 + 相对路径按 exe 目录解析（默认指到应用自带 ttf） |
| `InitFontFromFile` / `InitTextFormat` | 用 DirectWrite 3 从 ttf 直接建**私有字体集**（`CreateFontSetBuilder`→`CreateFontCollectionFromFontSet`），失败回退系统集合 / Microsoft YaHei；`font_size` 在此乘 `g_scale` |
| `ObtainBuffer` | 按后备缓冲纹理缓存 RTV / D2D Bitmap（flip-model） |
| `DrawD2D` / `DrawFallback` | 圆角+文字 / 纯色矩形兜底 |
| `ViewProc` / `EnsureViewSubclass` | 子类化 `FLUTTERVIEW`，仅在按钮矩形内拦截鼠标 |
| `OnButtonClick` | 按钮唯一分派点：`ScriptTryRun(true)`，自己不打日志（硬编码两段链已删除）；跑不起来时由 `ScriptReload` 的 verbose 分支**每次点击重打一行原因** |
| `CaptureView` / `CountCreamBand` | 视觉门控的两块基石：`PrintWindow(PW_RENDERFULLCONTENT)` 抓 `FLUTTERVIEW` 到顶朝下 32bpp DIB → 在目标点周围 ±200×±40 物理 px 内数奶油色像素并返回质心；由 `script_engine.inc` 的 `WaitForCreamAt` 调用（`g_capture` 无锁，靠 `g_scriptActive` 单飞） |
| `script_engine.inc` | 点击脚本：`ScriptReload(bool verbose)`（选文件 + 比对修改时间 + SRWLock 保护 + 失败原因缓存 `g_scriptErr`）+ `JsonParseScript`（精简 JSON：字符串转义/`\uXXXX`、数字、跳过未知键）+ `ScriptRunThread`（门控/滚轮/粘贴/三种点击/`loop`）+ `ScriptHotkeyThread`（可选全局热键，2s 轮询热加载，传 `false` 保持静默） |
| `StampPrefix` / `PushScreenLog` / `DrawScreenLog` | 界面日志：`LogFromOverlay` 的第二出口，每行先拼 `[HH:MM:SS.mmm]`（与文件日志同钟，重复行也能看出在滚），24 行环形缓冲（`SRWLOCK`）+ D2D 左下角的**常驻 tail -f 面板**（不淡出，新行滚到底、旧的推出窗口），帧内只读快照，不影响绘制路径 |
| `SetScriptStatus` / `g_statusLine` / `g_noScriptFile` | 脚本状态：`ScriptReload` 三个出口写入（0=接管 / 1=没脚本文件 / 2=被拒收），驱动常驻状态行；仅 1 时胶囊改用 `no_script_text` |
| `IsRelatedWindow` / `IsTargetSwapChain` | 匹配主窗口、子窗口、owned 弹窗 |
| `HookPresent/Present1/Resize` + `PatchVTable` | vtable 级 Present hook |
| `HookCreateDevice*` + `HookGetProcAddress` + `PatchIatForModule` | 给 D3D11 设备补 BGRA |
| `LdrRegisterDllNotification` | 模块加载即补丁，抢在 ANGLE 建 设备前 |

## 10. 合规提示
