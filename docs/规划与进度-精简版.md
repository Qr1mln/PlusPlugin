# TTVoice 改造 — 规划与进度（精简版）

> 浓缩自 `docs/改造开发-进度与交接.md` 与 `docs/plugin-framework.md`。细节以这两份为准。

## 1. 目标
无源码条件下，给 TTVoice（Flutter+ANGLE/D3D11，x64）顶栏加「活动」入口并程序化点击触发事件；做法 = `version.dll` 代理 + 注入式渲染。部署只需 `%APPDATA%\TTVoice\version.dll` 一个文件。

## 2. 当前状态
- **产品功能（P0–P2）已完成**：叠加层按钮 + 点击脚本引擎 + 屏上日志面板（tail -f 常驻）。
- **代码正在重构为插件框架**：M0（ABI/加载/卸载/日志分发）已落地；M1（渲染派发 + overlay 迁移）待做。`dllmain.cpp` 目前**双轨运行**（老单体 `overlay.inc` 仍生效 + 新插件框架已启动）。

## 3. 架构
```
TTVoice.exe → version.dll 代理(dllmain.cpp+stubs) → framework(loader+api+[M1]render) → plugins/
```
原则：**framework 拥有所有 hook/线程/系统注册点**；插件只通过 `TTPluginHost` 预订回调，故可运行时卸载。

| 层 | 文件 | 状态 |
|---|---|---|
| ABI 契约 | `sdk/ttplugin.h` | ✅ |
| 能力表(host 侧) | `framework/plugin_api.inc` | ✅ |
| 生命周期/控制 | `framework/plugin_loader.inc` | ✅ |
| 渲染派发+Present hook | `framework/render.inc` | 🟡 M1 未写（hook 暂留 overlay.inc） |
| 示例/日志插件 | `plugin_example/` `plugin_console/` | ✅ |
| 产品插件(按钮+脚本+日志) | `plugin_overlay/` | 🟡 M1 规划（由 overlay.inc+script_engine.inc 迁移） |
| 老单体代码 | `overlay.inc`(1566) `script_engine.inc`(832) | ⚠️ 仍生效，待删 |

## 4. 下一步（M1，最高优先级）
1. 写 `framework/render.inc`：接管 Present hook，每帧按 priority 调各插件 `addDraw`，输入子类化后按 `regions[]` 命中测试派发点击。
2. 把 `overlay.inc`+`script_engine.inc` 改写成 `plugin_overlay/`：绘制走 `addDraw`、点击走 `addRegion`、屏上日志走 `addLogSink`（ring+绘制复用 `plugin_console`）。
3. 删除顶层两个 `.inc`，`dllmain.cpp` 精简为"代理转发 + 引导 + 早期 D3D11 hook 线程 + `plugins::Start()`"。
4. 补信任链 `sha256`（M3 强制，plugin.json 字段已容忍）。

## 5. 关键风险
- 约 **2400 行脆弱原生图形代码**；**本机无 MSVC，无法编译验证**，需在 VM 完成并实测。
- 迁移期保留老路径并行、灰度切换，避免一次性断裂。
- 发布需 DLL 代码签名 + EDR 白名单沟通。

## 6. 构建/运行（VM）
```bat
:: 代理
native\version_proxy\build.bat
:: 插件（示例/控制台）
native\version_proxy\plugin_example\build_plugin.bat
native\version_proxy\plugin_console\build_plugin.bat
:: 部署
copy /y version.dll "%APPDATA%\TTVoice\version.dll"
:: 运行时控制 plugins\control.txt：load/unload/list <name>
:: 回滚：删除 %APPDATA%\TTVoice\version.dll
```
日志：`%TEMP%\tt_version_proxy.log`；插件目录：`%APPDATA%\TTVoice\plugins\<NNN-name>\`。
